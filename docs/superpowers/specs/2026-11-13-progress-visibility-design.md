# 서비스 설계 — 조별과제 진행 상황이 보이는 웹 (가칭 "어디까지 했어?")

## Context
W8 인터뷰(11명, 카드 238장)와 페르소나 3종(v6 번호: 김민수 P1·P4·P10 / 이수아 P3·P6·P11 / 한도윤 P2·P5·P8·P9)을 근거로 학기말 프로토타입으로 만들 서비스를 기획했다. 구현은 이 설계를 바탕으로 별도 구현 계획을 세운 뒤 시작한다.

## 왜 (근거)
- 팀장은 진행 상황을 한 명씩 물어봐야 하고 "사실상 진행 상황 물어보는 사람"이 된다 (P4-42, P4-46)
- 팀원은 남이 어디까지 했는지 몰라 언제 보낼지 고민한다 (P6-50, P6-64b)
- 도구를 들여도 안 쓴다: 노션 체크박스는 아무도 체크하지 않음(P4-44a), when2meet 링크 안 누름(P4-24a), 캘린더 초대 미수락(P7-10), 가입 귀찮음(P5-26a)
- 늦는다는 말·재촉이 부담스럽다: "안 된다는 말을 하기 편했으면"(P6-64a), 재촉처럼 보일까 봐 초안을 안 보냄(P6-38a)
- 연락 두절 시 팀장이 직접 연락·대신 처리한다 (P4-48a, P1-18b, P10-35a)

## 목표
- 팀원 모두(역할 구분 없이)가 한 화면에서 누가 어느 단계까지 왔는지 본다
- 진행 기록은 결과물을 올리는 것만으로 남는다 (별도 체크 없음)
- 늦을 때 사람에게 직접 말하지 않고도 사유와 함께 알릴 수 있다
- 학기말에 실제 동작하는 웹으로 시연한다 (여러 기기에서 같은 팀 화면, 올리면 바로 반영)

## 하지 않을 것 (비목표)
- 회의 시간 잡기 기능 (별도 고충이며 이번 범위 밖) — Claude 제안
- 팀 채팅 (단톡방을 대체하지 않는다) — Claude 제안
- 기여도 평가·점수화 — Claude 제안
- 실제 카톡 알림톡 발송 (사업자·심사 필요)

## 실패로 볼 것 (반목표)
- 노션처럼 결국 한 사람만 들어가는 도구가 되는 것
- 공개 망신·감시 도구처럼 느껴지는 것 (그래서 연장 요청이 핵심 장치)

## 핵심 흐름
1. **팀 만들기**: 누군가 과제 이름·팀 마감·과제 유형(발표/보고서/개발/직접)을 입력 → 팀 링크 생성 → 단톡방에 공유
2. **들어오기**: 링크를 누르고 이름만 입력 (가입·설치 없음; 이 기기에 기억) — Claude 제안
3. **단계 정하기**: 유형별 템플릿이 단계와 기한을 제안 (예: 발표 = 자료조사 → 초안 → 완성, 팀 마감에서 거꾸로 기한 배분). 팀 누구나 고칠 수 있음 — 한 사람에게 준비가 몰리지 않게
4. **맡기**: 각자 맡을 일(파트)을 적고, 파트마다 단계가 붙는다
5. **올리기 = 기록**: 단계마다 결과물(파일, 링크, 짧은 메모)을 올리면 그 단계가 완료로 표시되고 팀 화면에 바로 반영(실시간)
6. **연장 요청**: 기한 전에 본인이 사유와 연장 기간을 적으면 팀 알림이 가고 기한이 바로 바뀐다 (팀 승인 없음 — 승인 절차가 말하기 부담을 되살리므로, Claude 제안)
7. **기한 지남**: 단계 기한이 지나도 결과물이 없고 연장 요청도 없으면 팀 전체 알림
8. **알림**: 웹 안 알림 목록 + "카톡으로 공유" 버튼(단톡방에 바로 보냄). 시연 시 "실서비스는 카톡 알림"으로 설명

팀 화면 스케치:
```
[마케팅원론 기획서]            팀 마감 11/20   🔔3
 김○○  시장조사   자료 ●  초안 ●  완성 ○
 이○○  4P 분석    자료 ●  초안 ○  완성 ○   (초안 2일 연장 · 알바 일정)
 박○○  발표자료   자료 ○  초안 ○  완성 ○   ← 자료 기한 지남
```

## 방식 (Approaches)
| 안 | 장점 | 대가 |
|---|---|---|
| **Next.js + Supabase (선택)** | DB·파일 저장·실시간 갱신 일체, Vercel 링크 하나로 접속 | Supabase 계정·프로젝트 설정 필요 |
| React(Vite) + Firebase | 실시간·파일 저장 잘함 | 팀·단계·결과물처럼 얽힌 데이터에 덜 맞음 |
| 직접 서버(Node + SQLite) | 외부 서비스 없음 | 실시간·파일·배포를 직접 구현, 학기 일정에 과함 |

사용자가 Next.js + Supabase를 골랐다. 이유: "링크로 바로 들어옴"과 "올리면 모두에게 바로 보임"을 가장 적은 품으로 해결.

## 빌더에게 맡기는 것
- 화면 디자인 세부, 템플릿별 기본 기한 배분 비율
- 데이터 구조 (팀, 멤버, 파트, 단계, 결과물, 알림) 와 Supabase 권한 규칙 (팀 링크를 아는 사람만 접근)
- 기한 지남 판정 방식 (접속 시 계산 또는 예약 작업)
